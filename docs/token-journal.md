# Статистика

Пункт **«Статистика…»** в меню miniapp открывает журнал операций этой установки.
Столбцы: операция, время запуска, длительность, потраченные токены. Ошибки,
отмены и незавершённые операции отмечены в названии строки; подробности доступны
при наведении. Сверху — сумма известных входных и выходных токенов.
Окно доступно и при остановленном сервере, обновляется каждые пять секунд
и по кнопке «Обновить». Переименование не меняет папку журнала или старые записи.

## Какие операции попадают в журнал

| Источник | Запись и расход |
| --- | --- |
| Полная локальная проверка области/страницы | «Проверить», 0 токенов; native и контрактная ветви одного запуска объединены |
| Автоматическая перепроверка после действия | «Перепроверить область», 0; это отдельная частичная проверка |
| ReGlyph | Отдельные записи проверки и замены иконок, 0 |
| Переименование слоёв | Итог запуска, отдельно локальное применение и отмена замен; применение и отмена — 0 |
| Агентская проверка паттернов | Итог запуска; запросы агента содержат измеренный расход |
| Спросить, AI-проверки/пояснения, анализ пачек названий, planning и исполнители генерации | Существующие строки запросов/операций с фактическими счётчиками провайдера |

Открытие карточки, выбор соответствия, превью и переход к слою не являются
отдельным выполнением операции. Служебное чтение диагностики также не включено.
Повторный пользовательский запуск получает новый ID. Начало и завершение одной
локальной операции обновляют одну строку. Ошибка захвата до обращения к агенту
тоже оставляет запись. Статус «Завершено» означает завершение выполнения,
а не отсутствие нарушений или подтверждение всех норм.

Длительность локальных операций измерена в плагине. Итоговые строки запуска
переименования/проверки паттернов не добавляют повторно расход из агентских
запросов: после возможного обращения к агенту они показывают «Нет данных»
и пояснение, что токены учтены отдельно. Если обращение к агенту ещё не
предпринималось, расход локального этапа известен и равен 0.

## Учёт токенов

Codex возвращает фактические счётчики в `turn.completed`. Claude использует
итоговый `result.modelUsage`, а при его отсутствии — `result.usage`; сообщения
assistant и итог не складываются. В Claude вход включает обычные токены,
чтение кеша и создание кеша. Для Codex кеш уже является частью входа.
Выходные reasoning-токены повторно не прибавляются.

Если агент не передал полную статистику, строка показывает «Нет данных» либо
`≥ N`, когда известна только часть расхода. AlfaGen не имеет полного
usage-адаптера: его строки сохраняются с явной неполнотой расхода.
Расход в деньгах и остаток лимитов аккаунта не вычисляются.

## Сохранение и доставка локальных записей

Плагин использует одну очередь доставки в Figma clientStorage. У каждой операции
свой ключ `apollo.local-operation.v1:<id>`; общего перезаписываемого массива нет.
Независимые производители не заменяют записи друг друга. Отправляются только
ID, фиксированный вид операции, время старта, длительность, статус и признак
отдельного учёта модели. Текст, названия слоёв, содержимое макета и credentials
в эти записи не входят.

Начало сохраняется до доставки завершения. Запись удаляется из очереди только
после чтения полного ответа Proxy с совпавшими ID и статусом. Старое подтверждение
начала не удаляет уже сохранённое завершение. Повторы идемпотентны; конфликтующее
завершение отклоняется. Подтверждённое начало остаётся в durable-журнале Proxy.

При недоступном Proxy сохранённые записи остаются в Figma. Доставка повторяется
при открытии UI, появлении сети, через 30 секунд или по кнопке
**«Повторить отправку»**. Ошибочная запись не блокирует независимые корректные.
В интерфейсе проверки и внутри открытого окна навыка показывается единый статус
доставки. **«Скачать сведения»** экспортирует только безопасные метаданные очереди,
непринятые записи и ID непрочитанных записей для разбора ошибки.

Бюджет очереди: 256 записей / 256 KiB. Общая квота clientStorage может закончиться
раньше из-за других данных плагина. Лимит, ошибка сохранения, неподтверждённый
ответ и отказ Proxy показываются явно. При ошибке сохранения запись пока может
находиться только в памяти UI: повторите попытку или скачайте сведения до
закрытия окна. Недоставленные записи автоматически не удаляются ради лимита.
Телеметрия не блокирует проверку/замену и не меняет её результат.

Если UI аварийно исчез после сохранения начала, исход операции может остаться
неподтверждённым. Перезапуск Proxy не доказывает завершение локальной операции:
такие строки сохраняют незавершённый статус без выдуманной длительности.
Обычные ошибки и отмены закрываются по событиям соответствующего исполнителя.
Незакрытые Proxy-owned/model строки после аварии помечаются как прерванные при
следующем запуске; время простоя не считается длительностью операции.

## Хранилище и совместимость

Записи `apollo.token-operation.v1` хранятся отдельными JSON в
`APOLLO_STATE_ROOT/token-journal`. В dev-установке без явного state root —
`.local/token-journal` относительно рабочей папки сервера. Обновление данных
не затрагивает журнал. Старые диагностические usage receipts не импортируются.

`GET /usage` возвращает строки и число повреждённых записей. `POST /usage/local`
сохраняет только разрешённые локальные/итоговые операции; клиент не может задать
произвольный расход токенов. Старый запрос `operation=check` из пяти полей
по-прежнему принимается. Новый ответ содержит `success`, исходный `id`, `status`.
`usageMode=separate` допустим только для итогов переименования и проверки паттернов.
Чтение тела ответа входит в общий deadline доставки.

Новый UI со старым Proxy сохраняет неподтверждённые записи в очереди и показывает
необходимость обновления кода Proxy. Проверки продолжают работать. Замена
названия меню требует новой сборки самого miniapp; обновление знаний меню не меняет.

Регрессии: `test/token-journal.test.js`, `test/token-journal-native.test.js`;
Apollo: `tests/token-journal-client.test.js`, `tests/token-journal-native.test.js`,
`tests/token-journal.browser.cjs` и существующие lifecycle-тесты навыков/паттернов.
