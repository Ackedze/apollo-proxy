# Ответы АБМ в Apollo Proxy

Изменения относятся только к существующему маршруту «Спросить» Codex/Claude.
Обновлённый плагин передаёт `dialoguePlatform`: iOS/Android всегда выбирают
АБМ, Desktop/MobileWeb — обычный маршрут. Выбор имеет приоритет над текстом,
историей и сохранённым режимом сеанса. Неизвестное значение даёт HTTP 400.
Перед вызовом модели клиент проверяет `/health`: `capabilities.dialoguePlatformRouting: true`.
Ответ подтверждает библиотеку в `dialogueLibrary` (`abm` или `ab`); новый клиент
не показывает ответ без совпадающего подтверждения. Во время запроса и пока
агент занят переключатель платформы заблокирован. Stop отменяет только ожидание
на клиенте, не гарантируя остановку серверной задачи.
Без этого поля прежние клиенты выбирают режим по явному АБМ/ABM в вопросе или
контексте пользователя; явное АБ/AB возвращает обычный маршрут. Без АБМ прежний
промпт не меняется. AlfaGen при явно выбранном iOS/Android получает HTTP 503
`ABM_PROVIDER_UNSUPPORTED` до внешнего вызова: этот режим поддержан Codex/Claude.
Платформа здесь определяет библиотеку; формат ссылок на обе платформы сохраняется.
Если при iOS/Android текущий вопрос явно называет АБ/AB/Альфа-Бизнес, Proxy
без вызова модели возвращает уведомление: «Сейчас выбран поиск по паттернам АБМ.
Чтобы задать вопрос по АБ, выбери Desktop или MobileWeb в переключателе сверху».
Уведомление имеет `responseKind: library-selection-notice`, без версии знаний.
Без явного названия АБ вопрос остаётся в АБМ; скрытый смысл вопроса отдельной
моделью не классифицируется.

## Источники и поиск

Источники задаются через `CODEX_ABM_PATTERNS`: полный срез Hub `products/abm`
или прежняя папка оригинальных MD. Паттерны АБМ имеют приоритет над HIG, Material 2
и Material 3. Гайды используются только если паттерны не отвечают на отдельный вопрос,
с явным указанием семейства. Наличие ответа паттерна исключает гайды для этого вопроса. История и знания модели не восполняют пробелы.

`ABM-source.js` читает полные правила, контекст разделов, числовых родителей
и связанные примеры. Метаданные помогают искать, но не являются нормами.
`ABM-retrieval.js` строит локальный индекс по fingerprint исходных MD:
названия, ID, tags, заголовки и текст правил. Описательные заголовки
на одном уровне с [Rule] сохраняются как контекст раздела. Совпавший
по названию раздел подбирается целиком и передаётся в matchedSections
перед общими совпадениями из текста. Если тема запроса совпадает с названием
паттерна, подбирается весь паттерн: подразделы с повторением названия
не вытесняют остальные правила. Уточнение конкретного сценария по-прежнему
сужает поиск. Перестроение не вызывает модель.
Подбор для нескольких вопросов распределяется между темами. Добавляются
связанные разделы целиком и редкие ключевые термины. Локальный словарь
сопоставляет варианты вроде «подписать кнопку» и «нейминг», русские и английские
названия компонентов. Единственная однозначная опечатка в одно редактирование
может расширить запрос; неоднозначные варианты не исправляются автоматически.
История текущего чата АБМ передаётся каждому запросу: до 15 последних обменов,
не более 30 сообщений и 12000 символов текста после сжатия. Специальные слова
для продолжения не требуются. Старые сообщения представлены выдержками,
последние вопрос и ответ сохраняются подробнее. Названия уже цитировавшихся
гайдов остаются поисковыми подсказками; утверждения проверяются заново по
текущим источникам. Семейство гайда сохраняется в рамках темы; новая явная
тема и новый явно выбранный гайд меняют область поиска. Смена темы определяется
по метаданным документов, а не по наличию фиксированной фразы продолжения.
Пропущенные при сжатии части не восстанавливаются догадкой. Очистка чата и
перезапуск плагина сбрасывают память; отдельной модели-суммаризатора нет.
Лимиты и поведение истории АБ не меняются.

Модель получает ограниченный пакет полных правил и контекст родителей,
а не путь к папке. В этом сценарии отключены shell, apps, plugins, MCP,
web search и discovery навыков. Ответ вне переданных ruleId не принимается.
Для Codex Proxy сначала читает MCP inventory без запуска модели, добавляет
`mcp_servers.<name>.enabled=false` для каждого унаследованного сервера и проверяет
повторным чтением, что включённых серверов не осталось. Пустая таблица
`mcp_servers={}` для изоляции не используется. Если проверка не подтверждена,
возвращается `ABM_TOOL_ISOLATION_FAILED` до запуска модели; личный config не меняется.
Выбранные правила передаются целиком без потолка объёма или числа правил.
`coverageLimited` описывает иные ограничения покрытия; модель не должна выдавать неполную выборку
за полный перечень правил. Лексический поиск может пропустить семантически
близкую формулировку: это ограничение проверяется отдельными сценариями,
а не объявляется нулевым риском. Потолок размера источников и числа правил снят;
обязательные родители добавляются вместе с подправилом. Дочерние исключения
добавляются и при выборе общего правила, даже если их отделяет другой заголовок.
При нескольких вопросах сначала резервируются кандидаты для каждого.
Точный запрос раздела ограничивается этим разделом с дочерними условиями.
Для списка компонентов учитывается общий раздел определений в документации.

В JSON для модели patterns и contexts передаются один раз. Правила содержат
contextId и parentRuleIds; родительские тексты доступны как отдельные правила
того же file. Текст не обрезается и не пересказывается при сжатии.
Бюджет считается по всему сериализованному knowledge, включая указатели разделов.
Раздел имеет complete:false, если отобран только частично.

До и после агента проверяется fingerprint MD. Изменение/недоступность источника
даёт техническую ошибку, без подмены источниками АБ. knowledgeRelease указывает
`abm-local-<fingerprint>`, а не commit другого пакета.

## Текст и оформление

Ответ строго на заданный вопрос. Если контекст неясен, найден только похожий
случай, нет подтверждённого ответа или остаётся конфликт — утверждённый fallback.
Уточняющие вопросы, самостоятельные советы, вступления и заключения запрещены.
Конфликт оценивается с учётом платформ и условий; дату нельзя использовать
для самостоятельного выбора победителя.

Разрешён понятный пересказ с сохранением условий, исключений и ограничений.
Запрещено добавлять выводы, которых нет в источнике. JSON содержит дословную
цитату для проверки происхождения и отдельный понятный текст.
Подготовка пакета и проверка цитаты используют одну функцию нормализации:
у Markdown-ссылки сохраняется видимый текст, удаляется только адрес. Цитата,
проходящая через такую ссылку, не должна ошибочно отклоняться.
Обёртки заголовков, inline-code и выделения нормализуются без изменения слов.
Неподходящее оформление пересказа не означает отсутствие правила: после
проверки цитаты Proxy исправляет обёртки или показывает подтверждённую цитату
вместо пересказа, без повторного вызова модели. Неверный файл/ruleId,
несовпадение цитаты и выдуманный вопрос остаются отказом: HTTP 502 с технической
ошибкой, без фразы «Не нашёл ответа». Ошибка чтения источника даёт HTTP 503.
Настоящий kind:not_found сохраняет согласованный шаблон.

Диагностические события содержат только коды причин, индексы и счётчики.
Вопросы, ответы и цитаты в них не записываются.

Проверка цитаты не доказывает семантическую точность пересказа: она проверяется
инструкцией и ручными сценариями.

Разрешены абзацы, **жирный**, *курсив*, маркированные и нумерованные списки.
Таблицы, HTML и исполняемый код запрещены. Квадратные скобки в шаблонах
вроде «К [разделу]» допустимы как обычный текст; ссылки
по-прежнему собирает только Proxy.

Каждое правило — отдельный блок, сразу за ним его примеры:

> Текст первого правила
>
> 🍏 Пример · 🤖 Пример
>
> Текст второго правила
>
> 🍏 Пример · 🤖 Пример
>
> Паттерн: «Название», v.2.3

Только слово «Пример» является ссылкой, эмодзи остаётся снаружи.
🍏 означает iOS, 🤖 — Android. Связи и URL берутся кодом из MD.
Если своего примера нет, используется общий пример ближайшего числового
родителя из того же паттерна. Общий пример повторяется под каждым правилом.
Соседний пример, ссылка раздела и figma_url не заменяют пример правила.
Если дана одна платформа, показывается только она.

Если примера нет, после текста правила сразу идёт следующее правило или
подпись паттерна. Сообщение об отсутствии примера не выводится.
Для нескольких правил одного паттерна подпись с названием/версией выводится
один раз в конце группы. Версия строго из `version`, название из
`titlePage`/ `abmPatternTitle`. Даты, ID, разделы и «Источник» не выводятся.

## Несколько вопросов и отсутствие ответа

У каждого отвеченного вопроса — сам вопрос, затем его правила с примерами.
Все неотвеченные вопросы собраны в одном последнем блоке: заголовком идёт
утверждённая фраза, ниже список самих вопросов. При одном вопросе — только фраза.

Утверждённая фраза:

> Не нашёл ответа в паттернах АБМ. Напиши в чат «DS ABM :: Скорая помощь по дизайну» — мы ответим на твой вопрос

Название чата — ссылка на предоставленный владельцем xlink.achat.best URL,
закреплённый в `ABM-response.js`. Proxy ничего не отправляет в чат автоматически.
Потребность сигнализировать команде о пробелах/конфликтах сохраняется отдельным
этапом; получатели, хранение и канал такого сигнала ещё не утверждены.

## Подключение и проверка

Настройки установленного приложения не меняются. Для текущего локального теста
используется тот же checkout Proxy, отдельное dev-state и совместимые
runtime/данные. Дополнительного checkout или .command-файла нет.
Обычный Apollo Proxy должен быть выключен, когда тестовый процесс занимает
localhost:3001. В новом клиенте выбрать iOS или Android в верхнем переключателе;
для старого клиента в первом вопросе нового чата явно указать АБМ.
Для проверки переключателя требуется собрать и заново открыть плагин Apollo;
обновление одного Proxy не добавляет поле в старый плагин.

Регрессии на синтетических fixtures: `ABM-retrieval.test.js`,
`ABM-response.test.js`, `ABM-dialogue-runtime.test.js`, плюс прежние
`dialogue-source.test.js`, `dialogue-runtime.test.js`, `cli-agent.test.js`.
В текущем этапе реальный агент не вызывался: проверены fixtures и сохранённые ответы;
реальные вопросы, ответы и логи в Git не добавляются.

## Измерение текущего изменения

Один сравнительный запрос с двумя вопросами о форматировании сумм:
вход 98 039 → 22 350 токенов (примерно −77%); новая генерация заняла 11,2 с.
До изменения из 98 039 входных токенов 73 728 отмечены как кешированные,
в новом запросе кешированных токенов было 0. Эти значения не позволяют
напрямую предсказать процент пятичасового лимита. Это один замер, не бенчмарк
всех вопросов и не доказательство отсутствия потерь качества.

Предварительный подбор на 13 локальных формулировках в текущих MD нашёл
13 ожидаемых правил. Проверяются именно наличие ожидаемых источников и
сохранение контекста, а не все возможные ответы агента.

Известное ограничение прежнего test/dialogue-runtime.test.js:
после проверок обычного Ask он обращается к отсутствующему экспорту
assertGenerationRuntimeReady. В родительском коммите этот экспорт также
отсутствует. Этот отказ не исправляется изменениями сценария АБМ.


## Локальный аудит исходников без модели

```bash
node scripts/ABM-audit-search.js --patterns /path/to/patterns --output /tmp/abm-search-audit.json
```

Для Hub передавайте корень `products/abm` или его папку `patterns`; старый
плоский формат также поддерживается. Пустой набор считается ошибкой `NO_PATTERNS`.
Аудит не изменяет MD. Проверяет метаданные, дубли ключей, наличие родителей,
соответствие примеров правилам, платформы ссылок и текст после примеров.
Пустая группа с подправилами отмечается как info, а не как пустая норма.
Предупреждение не доказывает ошибку содержания; нормативную трактовку
автоматически не меняем.

В текущих 25 файлах / 595 правилах критических ошибок структуры не обнаружено.
Есть 5 уникальных групп примеров без отдельного Rule и ссылки без платформы,
требующие ручной сверки. Сами документы не правились.

Дополнительные регрессии: ABM-search-terms.test.js, ABM-audit.test.js.
Подтверждены сохранение текста при устранении повторов, отсутствие новых
вызовов модели и воспроизведение сохранённых ответов о нейминге и компонентах
выбора. Новый процент расхода лимита не измерялся.

Автоматического git pull в запросе нет. Нормативные MD и гайды не изменялись.


## Карточки рекомендаций гайдов в Apollo

Дополнительное поле `answerBlocks` содержит проверенные блоки `{kind: text, text}`
или `{kind: guide, family: hig|material2|material3, text}`. Вопросы и правила
паттернов остаются обычными блоками; рекомендации группируются по семейству
внутри каждого вопроса. Совместимое поле `result` содержит те же тексты в том же
порядке для старых клиентов. Модель не выбирает оформление: тип берётся из
проверенного source document. Клиент сверяет family и соответствие блоков result.
Новый Apollo объединяет все рекомендации в одну серую карточку «Рекомендации
гайдов», свёрнутую по умолчанию. Внутри остаются названия семейств и вопросы.
Блоки guide могут содержать question, а текстовые заголовки — questionHeading:true. Публичный старый плагин продолжит показывать обычный Markdown до выпуска.


Подпись гайда содержит ссылку на его название, если точный URL подтверждён.
`ABM-guide-links.json` сопоставляет guideID + title + family с официальной страницей
по индексам Apple HIG, Material 2 и Material 3. Отдельные API-документы, картинки
и соседние рекомендации не используются вместо страницы исходного гайда.
При отсутствии подтверждённого соответствия название остаётся обычным текстом.
URL проверяется по HTTPS/домену семейства и формируется кодом, а не моделью.
В запросе к модели нет дополнительного веб-поиска; версия MD остаётся источником
рекомендации, ссылка нужна только для перехода человека на сайт.


## Временный счётчик в ответе

`APOLLO_ASK_SHOW_TOKEN_USAGE=1` добавляет к ответу «Спросить» строку с фактическим
входом, выходом, кешированной частью входа и суммой вход+выход. По умолчанию
отключено. Значения берутся из request-scoped token journal, не из последней
записи на диске и не из оценки модели. Кеш не прибавляется повторно к сумме.
Если usage неполон, показывается отсутствие полного расхода; без вызова модели
показывается 0. Ошибки тоже получают счётчик, если клиент получил ответ.
API добавляет tokenUsage, а answerBlocks остаётся согласован с result.
Флаг включён только в изолированном запуске тестового Proxy.

Нерелевантные или неоднозначные рекомендации гайдов не добавляются. Их отсутствие
не отменяет подтверждённый ответ паттерна. Приоритет означает соблюдение нормы
АБМ при расхождении. Для каждого отдельного вопроса действует fallback: ответ
паттерна исключает гайды; при отсутствии ответа паттерна разрешены гайды.

Переключатель iOS/Android не является фильтром знаний АБМ. Платформенные условия
в ответе сохраняются явно; HIG, Material 2 и Material 3 не смешиваются в одну
универсальную норму и показываются отдельными разделами общей карточки.


## Язык рекомендаций гайдов

Русский пересказ формируется агентом при ответе; MD в Hub остаются исходными.
Раздел «Язык рекомендаций HIG / Material» в `src/reports/ABM-messages.js`
задаёт единый стиль для Codex и Claude в режиме АБМ:

- Русская техническая речь с английскими названиями компонентов, вариантов,
  ролей, состояний, токенов и API из конкретного источника.
- `secondary color` → «цветовая роль secondary»;
  `secondary action` → «дополнительное действие (secondary action)».
  Приоритет действия не задаёт цвет или вариант кнопки.
- `Filled tonal` → «кнопка Filled tonal»; `pressed` → «состояние pressed»;
  `touch target` → «область касания (touch target)»;
  `haptic feedback` → «тактильный отклик».
- `elevation` и тень не отождествляются. `tonal elevation` сохраняет собственное
  название. Написание цветовой роли из дизайн-гайда не преобразуется в API-токен.
- Названия Bottom sheet, Snackbar, Navigation rail, VoiceOver, TalkBack и
  Dynamic Type сохраняются в написании источника. Accessibility — «доступность».
- Padding — «внутренний отступ», margin — «внешний отступ», spacing — «расстояние
  между элементами»; это пояснения, а не переименование API или токенов.
- Selected и pressed различаются; одна сущность называется одинаково во всём
  ответе. Разные платформенные компоненты не объединяются ради единообразия.
- Естественные короткие фразы («нажми», «выбери», «перетащи») вместо канцелярита.
  Английские термины не заменяют русское объяснение; пояснение в скобках не
  повторяется при каждом упоминании.
- Сохраняются must/should/may, отрицания, числа, pt/dp/sp, ограничения устройств
  и версии гайдов. Примеры словаря определяют речь, но не добавляют норм.

`quote` остаётся дословной английской цитатой для проверки происхождения;
`text` — русский пересказ. Renderer сохраняет английские термины в общей
карточке гайдов. Проверка цитаты не доказывает смысловую точность перевода:
новый стиль задаётся инструкцией модели, без автоматической замены слов.
Дополнительного вызова модели, переводчика или новой зависимости нет;
фиксированная инструкция немного увеличивает входной контекст.
Обычная выдача АБ и правила паттернов не получают этот словарь.

Ориентиры терминологии (это справка разработчику, не новые RAG-источники):

- [Material 3: Color roles](https://m3.material.io/styles/color/roles) — роли цвета.
- [Android: Material 3 в Compose, русский текст](https://developer.android.com/develop/ui/compose/designsystems/material3?hl=ru) — цветовые роли и точные API-идентификаторы.
- [Android: Button](https://developer.android.com/develop/ui/compose/components/button?hl=en) — варианты кнопок и приоритет действий различаются.
- [Apple HIG: Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) — стили и роли кнопок.

Русская локализация полезна для сверки, но не заменяет исходную терминологию
английского гайда. Внешний [Google Cloud Translation glossary](https://docs.cloud.google.com/translate/docs/advanced/glossary)
позволяет настроить словарь для отдельного API перевода; в этот процесс он
не подключён. Пользователю не требуется дополнительный промпт.


Визуальная иерархия ответа: инструкция агента просит начинать `evidence.text`
с короткой ключевой мысли, выделенной жирным, сохраняя условия и исключения.
Название паттерна, версия и примеры по-прежнему формируются Proxy из источника.
Обновлённый Apollo оформляет эти подписи и прячет технические сведения в
«Детали ответа»; схема, поиск и число вызовов модели не меняются.


## Мобильная область и русские запросы к гайдам

`src/reports/ABM-guide-search.js` содержит отдельный словарь поиска гайдов,
не словарь нормативных переводов. Составная русская формулировка расширяет
локальный запрос английскими терминами. Примеры: «область нажатия» → touch
target; «подпись кнопки» → button label; «экранный диктор» → screen reader.
Внутренний отступ ищет padding, внешний — margin, расстояние между элементами —
spacing. Selected и pressed различаются; неоднозначные «подсказка», «тост»
и «тень» не превращаются автоматически в placeholder, Snackbar и elevation.
Полное совпадение составного термина с заголовком раздела повышает его ранг.

Фильтр до ранжирования/бюджетирования гайдов исключает документы и ветви с
явной областью watches/Wear OS, XR/visionOS, desktop/macOS/ChromeOS, TV и
автомобильных интерфейсов. Общие рекомендации, телефоны, foldables и планшеты
остаются; iPadOS-разделы HIG разрешены. Упоминание desktop в сравнении внутри
мобильного текста само по себе не удаляет полезное правило. Смешанный раздел
может содержать сведения нескольких устройств; инструкция агента разрешает
использовать только явно применимую мобильную часть с условиями. Это не
семантический классификатор каждого предложения, и точность такого пересказа
по-прежнему требует проверки на реальных ответах.

Явный вопрос о часах не отключает продуктовый мобильный фильтр. Выбор iOS или
Android по-прежнему включает одну и ту же библиотеку всех трёх семейств.
Паттерны приоритетны. Отсутствующий мобильный Material 3 не восполняется
советами для часов и не маскируется переименованием Material 2.

Обычный АБ не затрагивается. Индекс и веса паттернов АБМ сохраняют прежнюю
схему; новые расширения применяются только к отдельной ветви поиска гайдов.
Исходные MD, цитаты и ссылки сохраняются. Потолок размера источников и числа
правил отменён владельцем; лимит истории диалога рассматривается отдельно.
исключённых разделов и выбранных разделов каждого семейства, без текста
вопросов. Дополнительных вызовов модели и платного перевода нет.


## Гайды только при отсутствии ответа паттерна

Для каждого элемента `answers` сначала используются паттерны. Если в этом
ответе есть подтверждённые evidence паттерна, `ABM-response.js` исключает
все guide evidence после проверки каждой цитаты. Отсутствие ответа на другой
вопрос не скрывает его гайды. Неподтверждённая цитата остаётся ошибкой,
а конфликт паттернов не разрешается через гайд. Состав источников определяется
моделью по релевантности; код гарантирует раздельную выдачу выбранных источников,
но не доказывает смысловую полноту ответа паттерна. Повторного вызова нет.


## Занятость агента в чате

Отказ из-за активного локального запроса возвращает HTTP 429 с кодом
`APOLLO_AGENT_BUSY`. Глобальный запрет параллельных запросов сохранён.
Новый Apollo читает занятость из health до отправки; при гонке отклонённая
попытка удаляется из клиентской переписки, вопрос восстанавливается в черновике.
Клиент показывает спокойный статус вместо сырой ошибки с нулевыми токенами.
Повторной отправки по таймеру и новых вызовов модели нет. Старый клиент
продолжает получать прежний HTTP-статус и текст. Серверная отмена не менялась.


## Явный запрос только гайдов

В режиме АБМ слова HIG (также HIK/ХИГ/ХИК), Material 2, Material 3 или
явное общее упоминание гайдов включают `guideOnly`. Названные семейства
образуют объединение: HIG + Material 2 не исключают друг друга. Общее
«в гайдах» выбирает все три семейства; Material без версии — оба Material.
Прямое «без гайдов» не включает этот режим. Это локальные лексические
признаки запроса, а не отдельный классификатор моделью.

Пакет исключает паттерны до бюджетирования; агент получает только выбранные
мобильные гайды, с прежними цитатами, ссылками и ограничениями. Политика
«сначала паттерны» заменяется инструкцией только по гайдам. Ответ состоит
из `kind:text`, поэтому и старый совместимый клиент не создаёт серую карточку.
Семейство и название документа сохраняются в подписи «Гайд: …». Если ответа
нет, сообщение говорит об отсутствии ответа в выбранных гайдах, а не в
паттернах, которые не искались.

«А ещё?» наследует тему и семейство последнего содержательного вопроса.
«А что в Material 3?» берёт предыдущую тему и меняет семейство на M3.
Новый содержательный вопрос без названия гайда снова использует обычный
порядок: паттерны, затем fallback-гайды в серой карточке. Переключатель
Desktop/MobileWeb и обычный маршрут АБ не меняются. Дополнительных вызовов
модели, загрузки документации или изменения MD нет.
