# Ответы АБМ в Apollo Proxy

Изменения относятся только к существующему маршруту «Спросить» Codex/Claude
при явном АБМ/ABM в вопросе или наследуемом контексте пользователя.
Явное АБ/AB возвращает прежний маршрут АБ. Без АБМ прежний промпт не меняется.
Выбор платформы текущий плагин в запрос диалога не передаёт.

## Источники и поиск

Единственные нормативные источники — исходные MD с `abmDocumentType: Pattern`
и `abmPatternID` из `CODEX_ABM_PATTERNS`. История, знания модели и гайды
не восполняют пробелы. Паттерны имеют приоритет и при будущем добавлении гайдов.

`ABM-source.js` читает полные правила, контекст разделов, числовых родителей
и связанные примеры. Метаданные помогают искать, но не являются нормами.
`ABM-retrieval.js` строит локальный индекс по fingerprint исходных MD:
названия, ID, tags, заголовки и текст правил. Описательные заголовки
на одном уровне с [Rule] сохраняются как контекст раздела. Совпавший
по названию раздел подбирается целиком и передаётся в matchedSections
перед общими совпадениями из текста. Если тема запроса совпадает с названием
паттерна, подбирается весь паттерн: подразделы с повторением названия
не вытесняют остальные правила. Уточнение конкретного сценария по-прежнему
сужает поиск. Перестроение не вызывает модель.
Подбор для нескольких вопросов распределяется между темами. Добавляются
связанные разделы целиком и редкие ключевые термины. Локальный словарь
сопоставляет варианты вроде «подписать кнопку» и «нейминг», русские и английские
названия компонентов. Единственная однозначная опечатка в одно редактирование
может расширить запрос; неоднозначные варианты не исправляются автоматически.
Короткое уточнение использует последнюю содержательную тему пользователя.
Явно новый вопрос без совпадений не подменяется старой темой. «А на Android?»
и «Покажи примеры» наследуют тему, как и «А ещё?» / «Продолжи». Без предыдущей
темы короткое продолжение не запускает поиск по слову «ещё». При продолжении
модель получает указание раскрывать оставшиеся правила без повторения ответа.
«Примеры чекбоксов» задаёт тему явно.

Модель получает ограниченный пакет полных правил и контекст родителей,
а не путь к папке. В этом сценарии отключены shell, apps, plugins, MCP,
web search и discovery навыков. Ответ вне переданных ruleId не принимается.
Правило не разрезается посередине ради бюджета. Непоместившиеся кандидаты
помечаются `coverageLimited`; модель не должна выдавать неполную выборку
за полный перечень правил. Лексический поиск может пропустить семантически
близкую формулировку: это ограничение проверяется отдельными сценариями,
а не объявляется нулевым риском. Пакет ограничен 64 000 символами и 128 правилами;
обязательные родители добавляются вместе с подправилом. Дочерние исключения
добавляются и при выборе общего правила, даже если их отделяет другой заголовок.
При нескольких вопросах сначала резервируются кандидаты для каждого.
Точный запрос раздела ограничивается этим разделом с дочерними условиями.
Для списка компонентов учитывается общий раздел определений в документации.

В JSON для модели patterns и contexts передаются один раз. Правила содержат
contextId и parentRuleIds; родительские тексты доступны как отдельные правила
того же file. Текст не обрезается и не пересказывается при сжатии.
Бюджет считается по всему сериализованному knowledge, включая указатели разделов.
Раздел имеет complete:false, если отобран только частично.

До и после агента проверяется fingerprint MD. Изменение/недоступность источника
даёт техническую ошибку, без подмены источниками АБ. knowledgeRelease указывает
`abm-local-<fingerprint>`, а не commit другого пакета.

## Текст и оформление

Ответ строго на заданный вопрос. Если контекст неясен, найден только похожий
случай, нет подтверждённого ответа или остаётся конфликт — утверждённый fallback.
Уточняющие вопросы, самостоятельные советы, вступления и заключения запрещены.
Конфликт оценивается с учётом платформ и условий; дату нельзя использовать
для самостоятельного выбора победителя.

Разрешён понятный пересказ с сохранением условий, исключений и ограничений.
Запрещено добавлять выводы, которых нет в источнике. JSON содержит дословную
цитату для проверки происхождения и отдельный понятный текст.
Подготовка пакета и проверка цитаты используют одну функцию нормализации:
у Markdown-ссылки сохраняется видимый текст, удаляется только адрес. Цитата,
проходящая через такую ссылку, не должна ошибочно отклоняться.
Обёртки заголовков, inline-code и выделения нормализуются без изменения слов.
Неподходящее оформление пересказа не означает отсутствие правила: после
проверки цитаты Proxy исправляет обёртки или показывает подтверждённую цитату
вместо пересказа, без повторного вызова модели. Неверный файл/ruleId,
несовпадение цитаты и выдуманный вопрос остаются отказом: HTTP 502 с технической
ошибкой, без фразы «Не нашёл ответа». Ошибка чтения источника даёт HTTP 503.
Настоящий kind:not_found сохраняет согласованный шаблон.

Диагностические события содержат только коды причин, индексы и счётчики.
Вопросы, ответы и цитаты в них не записываются.

Проверка цитаты не доказывает семантическую точность пересказа: она проверяется
инструкцией и ручными сценариями.

Разрешены абзацы, **жирный**, *курсив*, маркированные и нумерованные списки.
Таблицы, HTML и исполняемый код запрещены. Квадратные скобки в шаблонах
вроде «К [разделу]» допустимы как обычный текст; ссылки
по-прежнему собирает только Proxy.

Каждое правило — отдельный блок, сразу за ним его примеры:

> Текст первого правила
>
> 🍏 Пример · 🤖 Пример
>
> Текст второго правила
>
> 🍏 Пример · 🤖 Пример
>
> Паттерн: «Название», v.2.3

Только слово «Пример» является ссылкой, эмодзи остаётся снаружи.
🍏 означает iOS, 🤖 — Android. Связи и URL берутся кодом из MD.
Если своего примера нет, используется общий пример ближайшего числового
родителя из того же паттерна. Общий пример повторяется под каждым правилом.
Соседний пример, ссылка раздела и figma_url не заменяют пример правила.
Если дана одна платформа, показывается только она.

Если примера нет, после текста правила сразу идёт следующее правило или
подпись паттерна. Сообщение об отсутствии примера не выводится.
Для нескольких правил одного паттерна подпись с названием/версией выводится
один раз в конце группы. Версия строго из `version`, название из
`titlePage`/ `abmPatternTitle`. Даты, ID, разделы и «Источник» не выводятся.

## Несколько вопросов и отсутствие ответа

У каждого отвеченного вопроса — сам вопрос, затем его правила с примерами.
Все неотвеченные вопросы собраны в одном последнем блоке: заголовком идёт
утверждённая фраза, ниже список самих вопросов. При одном вопросе — только фраза.

Утверждённая фраза:

> Не нашёл ответа в паттернах АБМ. Напиши в чат «DS ABM :: Скорая помощь по дизайну» — мы ответим на твой вопрос

Название чата — ссылка на предоставленный владельцем xlink.achat.best URL,
закреплённый в `ABM-response.js`. Proxy ничего не отправляет в чат автоматически.
Потребность сигнализировать команде о пробелах/конфликтах сохраняется отдельным
этапом; получатели, хранение и канал такого сигнала ещё не утверждены.

## Подключение и проверка

Настройки установленного приложения не меняются. Для текущего локального теста
используется тот же checkout Proxy, отдельное dev-state и совместимые
runtime/данные. Дополнительного checkout или .command-файла нет.
Обычный Apollo Proxy должен быть выключен, когда тестовый процесс занимает
localhost:3001. В первом вопросе нового чата явно указать АБМ.

Регрессии на синтетических fixtures: `ABM-retrieval.test.js`,
`ABM-response.test.js`, `ABM-dialogue-runtime.test.js`, плюс прежние
`dialogue-source.test.js`, `dialogue-runtime.test.js`, `cli-agent.test.js`.
В текущем этапе реальный агент не вызывался: проверены fixtures и сохранённые ответы;
реальные вопросы, ответы и логи в Git не добавляются.

## Измерение текущего изменения

Один сравнительный запрос с двумя вопросами о форматировании сумм:
вход 98 039 → 22 350 токенов (примерно −77%); новая генерация заняла 11,2 с.
До изменения из 98 039 входных токенов 73 728 отмечены как кешированные,
в новом запросе кешированных токенов было 0. Эти значения не позволяют
напрямую предсказать процент пятичасового лимита. Это один замер, не бенчмарк
всех вопросов и не доказательство отсутствия потерь качества.

Предварительный подбор на 13 локальных формулировках в текущих MD нашёл
13 ожидаемых правил. Проверяются именно наличие ожидаемых источников и
сохранение контекста, а не все возможные ответы агента.

Известное ограничение прежнего test/dialogue-runtime.test.js:
после проверок обычного Ask он обращается к отсутствующему экспорту
assertGenerationRuntimeReady. В родительском коммите этот экспорт также
отсутствует. Этот отказ не исправляется изменениями сценария АБМ.


## Локальный аудит исходников без модели

```bash
node scripts/ABM-audit-search.js --patterns /path/to/patterns --output /tmp/abm-search-audit.json
```

Аудит не изменяет MD. Проверяет метаданные, дубли ключей, наличие родителей,
соответствие примеров правилам, платформы ссылок и текст после примеров.
Пустая группа с подправилами отмечается как info, а не как пустая норма.
Предупреждение не доказывает ошибку содержания; нормативную трактовку
автоматически не меняем.

В текущих 25 файлах / 595 правилах критических ошибок структуры не обнаружено.
Есть 5 уникальных групп примеров без отдельного Rule и ссылки без платформы,
требующие ручной сверки. Сами документы не правились.

Дополнительные регрессии: ABM-search-terms.test.js, ABM-audit.test.js.
Подтверждены сохранение текста при устранении повторов, отсутствие новых
вызовов модели и воспроизведение сохранённых ответов о нейминге и компонентах
выбора. Новый процент расхода лимита не измерялся.
