# Генерация через прямой CLI → Figma MCP

Apollo предоставляет чат и контекст файла. Proxy запускает Codex CLI,
предоставляет установленный пакет знаний и сохраняет сессию/историю. Агент
непосредственно читает и меняет Figma через remote MCP. Активный runtime —
`src/landing/direct-service.js`, workflow `direct-cli-mcp-v1`.

Первое успешное чтение может вернуть `target.rootNodeId=null` и `ownedCount=0`:
корень этого чата ещё не создан. При совпадении page/parent/owner это допускает
дальнейшее создание, но не привязывает root и не подтверждает готовность каркаса.
Неоднозначный результат или отсутствие ранее подтверждённого корня останавливает
работу с сохранением ID. Проверки принадлежности и согласование структуры сохраняются.

Proxy добавляет в чат точную причину host-остановки и передаёт её следующему CLI
как `hostFailure`. Успех очищает текущую причину, история отказов остаётся.
`AGENT_MCP_STARTUP_TIMEOUT` отдельно обозначает тайм-аут инициализации MCP, до
чтения canvas. Отсутствующий результат прерванного wrapper не доказывает отмену
входящим сообщением пользователя или изменение макета.

## Запуск и источники

Каждый fresh start и resume получает один pinned installed package и настройки
CLI без host skill discovery, bundled/implicit skill instructions, shell,
apps/plugins и web search. Глобальная конфигурация пользователя не меняется.
Сессия сохраняется: `exec resume <sessionId>` продолжает её с теми же настройками.

`apollo_knowledge` — read-only stdio MCP, только `list_sources/read_source`.
Он переиспользует `openKnowledge`, существующий reader и Hub routing; нового
роутера или копии норм нет. Источники — установленная Hub-проекция, выбранный
навык и bundled technical workflow. Внешние репозитории/контракты недоступны.
Пакетный sourcePin проверяется при запуске и чтении, фактические чтения фиксируются
из доставленных MCP результатов. Изменение pinned источников останавливает продолжение.

`apollo_figma_mcp` подключается напрямую к `https://mcp.figma.com/mcp`.
Аутентификация и доступность инструментов устанавливаются при реальном запуске;
наличие URL или health не доказывает возможность записи.

## Состояния

- `running` — работает CLI; UI показывает сообщения/прогресс и Stop.
- `needs-input` — существенный вопрос пользователю.
- `needs-structure-approval` — показан фактический каркас; до явного согласия
  Proxy не запускает наполнение. Отказ ждёт описания правки и нового согласования.
- `interrupted` — сохранены история, sessionId, checkpoint, actual IDs и ошибки.
  Продолжение сначала читает фактический owned root, не повторяет запись вслепую.
- `completed` — результат агента; проверки остаются agent-reported, Ready=false.

Контейнеры, Body, компоненты, modes, размеры и отступы выбирает агент по Hub.
Proxy не содержит их значений. Root принадлежит конкретному чату/ownerNonce;
фактические target IDs приходят из MCP результата. После смены вложенных ID
агент перечитывает дерево от корня. Stop/source/ownership и структура до контента
сохраняются, но прежние nativePlan и host preparation-переходы не участвуют.

## API и история

`GET /landing/status`, `GET/POST /landing/chats`, `GET /landing/chats/:id`,
`POST .../messages`, `.../structure-decision`, `.../cancel`, `.../delete`.
`canvas/native/observation/failure` возвращают410 `LANDING_LEGACY_FLOW_RETIRED`.
Старые записи доступны read-only и удаляются только из истории по запросу.
Автоматического resume/fallback на прежний service нет; его исходники оставлены
для отдельного рефакторинга, не импортируются текущим runtime.

Клиенту нужен прямой packaged workflow навыка0.6.0. Старый пакет не активируется
как запасной механизм. Выпуск совместимой пары — отдельный этап; установленное
приложение/данные не обновляются изменением исходников.

## Проверка

Тесты покрывают прямой CLI start/resume, изоляцию/stdio reader, approval,
Stop/recovery, дедупликацию запросов, исторические чаты и retired endpoints.
UI проверяется на фиксированной ширине800px. Mock/синтетические проверки не
доказывают качество полного живого лендинга. Сохраняются actual CLI/MCP traces,
usage и ошибки; успешная запись или модельный PASS не означают DS/визуальную приёмку.
