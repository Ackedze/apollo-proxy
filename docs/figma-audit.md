# Проверка выбранной области по DSI Hub

`ab-audit-figma` — отдельный инструмент Apollo. Он читает выбранную область,
сопоставляет компоненты и композицию с установленными знаниями DSI Hub и
возвращает нарушения, покрытие и фактический usage CLI.

После установки совместимых Apollo, Proxy и данных: выделите область Figma,
откройте «Тулзы» → «Проверка по DSI Hub» → «Проверить область». Остановка
отменяет работу агента. «Показать слой» меняет только выделение и viewport.
Отчёт скачивается как JSON; незавершённая проверка тоже сохраняет данные.
Установку обновлений и ручную приёмку в Figma выполняет владелец.

## Граница чтения

Модель работает в профиле `figma-audit` без shell, MCP, файловых действий,
приложений, плагинов и web search. Она запрашивает только фиксированные действия
host: поиск/чтение знаний, чтение узлов/наблюдённого источника, план и отчёт.
Произвольный JavaScript в Figma не выполняется. Native bridge не содержит
операций изменения сценовых узлов, импорта или создания временных экземпляров.

Корни берутся из выделения. Чтение ограничено их потомками; источник
допускается только по реально возвращённому `main.id`. Плагин собирает public
props, геометрию/layout/sizing, paints, bindings, text ranges, styles/variables
и эффективные значения. MIXED и ошибки чтения сохраняются явно. Источники
переопределений читаются независимо. Перед выдачей результата перечитываются
использованные факты. После результата page-node events помечают отчёт stale.

Пределы пилота:1000узлов карты,12узлов адресного чтения,6фрагментов документов
за шаг,40модельных шагов,15минут на прогон. Превышение бюджета останавливает
прогон; обязательные факты не обрезаются молча. Native ответы ограничены
400000UTF-8байтами. Документы выдаются по12000UTF-16символов, с `next`.

Скрытые ветви исключаются явно; remote master может быть недоступен или не
иметь parent. Скриншоты, поведение и другие viewport в этот пилот не входят.
Observer не гарантирует постоянную актуальность стилей/переменных/других
страниц; final reread проверяет использованные факты к завершению. Это
проверка статического состояния, не атомарный снимок всего документа.

## Нормы и результат

Знания — только pinned `knowledge/data/ds-ai-hub/**` и процедура выбранного
навыка. Нормы не дублируются в plugin predicates и не подменяются контрактами
Apollo. Приоритеты, платформенные ограничения, делегирование паттернов и
статусы знаний задаёт Hub. Непрочитанный документ не считается отсутствующим.

До оценки агент перечисляет пары «правило × целевой узел» и нужные поля.
Расширение плана не может удалять прежние строки. PASS/FAIL/NOT_APPLICABLE
требуют цитату прочитанного фрагмента Hub и native evidence целевого узла.
FAIL также содержит actual, expected, reason и fix. Host проверяет структуру,
происхождение ссылок и арифметику. Семантическая правильность интерпретации
норм остаётся результатом модели, а не доказательством валидатора.

Матрица включает PASS, FAIL, UNKNOWN, NOT_CHECKED, NOT_APPLICABLE.
Покрытие=(PASS+FAIL)/(все строки−NOT_APPLICABLE). Это покрытие объявленного
набора правил. Отдельно host показывает количество подробно прочитанных
узлов и ID экземпляров без чтения identity. Неохваченные семейства и
недостающие знания должны оставаться видимыми в excluded/gaps.

## Usage и evidence

Реальные input/output и доступные cache/reasoning поля CLI учитываются по
фазе вызова: documentation, figma, report. Общий контекст входит в каждую
фазу; это не распределение отдельных токенов смешанного контекста. Native
операции сами токены модели не расходуют. При отсутствии usage — null,
а не оценка; cached/reasoning являются подмножествами и не прибавляются.
Стоимость и число внутренних итераций провайдера не угадываются.

В каталоге состояния Proxy, под `figma-audit`, сохраняются run JSON и traces
с точными per-step input/output, usage, хешами, snapshot/evidence и источниками
с SHA256 и прочитанными диапазонами. Usage также попадает в журнал Proxy.
Синтетические usage fixtures тестов не являются расходом реальной модели.

## Доставка и протокол

Data-only пакет `apollo.skill-package.v3`, executor `apollo.figma-audit`,
runtime capability `figmaAudit=figma-audit-v1`. Старый/неизвестный runtime
отклоняет такой пакет до активации. Генераторы продолжают использовать свои
v1/v2 descriptors; audit не добавляется в список навыков генерации.

Маршруты: `GET /skills/figma-audit/status`, `POST /runs`, `GET /runs/:id`,
`POST /runs/:id/context`, `POST /runs/:id/cancel` под тем же префиксом.
Каждый ответ привязан к requestId/runId/snapshotId; native context — ещё и к
callId. Повторный requestId с другим входом и устаревший context отклоняются.
Схема wire — `apollo.figma-audit.v1`; её несовместимое изменение требует
новой версии и совместимого runtime/data выпуска.

Producer `refreshCatalog(sourceRoot)` обновляет descriptor/file pins и
центральный `apollo/skills/manifest.json` отдельно от публичного
`apollo/data-packages/current.json`. Это подготовка исходников; публикация,
обновление публичных указателей и установка выполняются отдельно.
