# Подключение Figma в Apollo Proxy

Figma подключается отдельно от аккаунта Codex. Подключение требуется для
генерации через Figma MCP. Проверка макета и «Спросить» работают без него.

1. В меню AP откройте **О прокси…** и выберите Codex.
2. Войдите в свой аккаунт Codex, если вход ещё не выполнен.
3. В разделе **Figma** нажмите **Подключить Figma** и подтвердите доступ
   в открывшемся браузере. Ожидание можно отменить в Proxy.
4. Дождитесь статуса **Figma подключена**. Он появляется после успешного
   входа и проверки живого MCP-соединения. Затем повторите генерацию.

При истёкшей или отозванной авторизации нажмите **Подключить повторно**.
Если Proxy не смог проверить соединение, проверьте сеть и нажмите
**Проверить подключение**. Такой результат сам по себе не означает,
что авторизация потеряна. Неудачная попытка не удаляет историю или макет.

Подключение не подтверждает право записи в каждый файл Figma. Выбранный файл,
доступ пользователя и возможность редактирования проверяются отдельно при работе.

## Реализация и границы

Proxy запускает официальный `codex mcp login apollo_figma_mcp` для
`https://mcp.figma.com/mcp`. Если такого подключения ещё нет, только по нажатию
**Подключить Figma** официальный `codex mcp add` создаёт эту одну запись. Прочие
подключения и настройки сохраняются. Уже совпадающая запись используется повторно;
если `add` сам завершил OAuth, второй вход не запускается. Хранением и обновлением
OAuth-данных занимается Codex, отдельного хранилища Proxy нет.

Перед входом и проверкой `config/read` сверяет фактическую конфигурацию. При
конфликте URL, транспорта, заголовков, auth/helper/env или неизвестных настроек
существующая запись сохраняется и возвращается отдельный **конфликт настроек**.
Proxy не сбрасывает её, не копирует секретные заголовки в аргументы запуска и не
создаёт другой `CODEX_HOME`. Для стандартного подключения нужно освободить имя
`apollo_figma_mcp`, сохранив своё пользовательское подключение под другим именем,
либо согласованно изменить его настройки в Codex; затем повторить подключение.
Проверка готовности, запуск приложения и генерация конфигурацию не меняют.

Вход, проверка и `landing-direct` используют общий helper
`src/figma-mcp/connection.js`, выбранный бинарник Codex и одинаковый набор
переменных окружения, включая `HOME`/`CODEX_HOME`. Если эти пути заданы явно,
они должны быть абсолютными: относительный профиль не переносится во временную
папку проверки или входа. Используется одинаковый режим
официального хранилища `mcp_oauth_credentials_store="auto"`. Корпоративные
requirements/политики Codex сохраняют действие; неподдержанная версия CLI
возвращает непроверенное состояние вместо фиктивного успеха.

Проверка открывает отдельный процесс `codex app-server`, выполняет
`initialize`, немутирующий `config/read` и адресный `mcpServerStatus/list`, затем завершает процесс.
Подтверждение требует результата живой инициализации, OAuth-статуса и доступного
`use_figma`. Наличие конфигурации, токена или кэшированного каталога недостаточно.
Проверка не создаёт thread/turn, не вызывает модель и не исполняет инструменты
Figma. Она имеет предел времени, поддерживает отмену и удаляет временную папку.

Перед генерацией соединение проверяется повторно. `Auth required` конкретного
`apollo_figma_mcp` получает отдельное сообщение с действием подключения;
первоначальные stderr/диагностика сохраняются в приватном failure trace.
Сетевая ошибка и отказ доступа к конкретному файлу не объявляются потерей OAuth.

Официальные API: [MCP](https://learn.chatgpt.com/docs/extend/mcp),
[CLI](https://learn.chatgpt.com/docs/cli/reference),
[App Server](https://learn.chatgpt.com/docs/app-server).

## Поставка

Кнопки и управление процессом находятся в Swift-приложении: для их доставки
нужна новая сборка ApolloProxyControl. Обновление только JS-кода Proxy из Git
не добавляет эти кнопки в уже установленное приложение. Публикация приложения,
установка, реальный OAuth и ручная проверка выполняются отдельными действиями.

Нативный адаптер выбирает и проверяет ту же текущую версию из code-store,
которую запускает генерация. После обновления JS он не использует старую
копию helper из bootstrap-каталога. Если текущая версия ещё не поддерживает
подключение либо обновляется, показывается действие запуска/обновления/повторной
проверки. При изменении версии во время входа результат не выдаётся за
подтверждение для нового кода.
