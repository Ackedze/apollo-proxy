# Передача Apollo Proxy коллеге и его агенту

Дистрибутив — версионный `ApolloProxyControl-macOS-<build>.zip`. Код и начальные
данные находятся в архиве. Пользователю нужны macOS 13+, собственный аккаунт
выбранного агента и доступ к используемой модели. Личные настройки и аккаунт автора
не передаются. Новый remote data channel начинает работать после отдельной
публикации `stable.json` и соответствующего архива; до этого встроенные данные
доступны офлайн.

Первая поставка поддерживает проверку, «Спросить» и Figma MCP. Frontend отключён
в её данных с явной причиной; переносимость frontend через собственный SDK —
следующий шаг. Установка SDK или сохранённый путь сами по себе эту возможность
не включают. Исходники и proof-файлы SDK в архив не входят.

## Короткая инструкция дизайнеру

1. Заверши прежний AP через «Выйти», если он уже запущен.
2. Распакуй ZIP в Finder и перенеси `ApolloProxyControl.app` в «Программы».
3. Открой приложение. Для внутренней ad-hoc сборки, заблокированной macOS,
   выполни команду для полученного от команды приложения:

   ```bash
   xattr -dr com.apple.quarantine /Applications/ApolloProxyControl.app
   open /Applications/ApolloProxyControl.app
   ```

4. В строке меню открой AP → «О прокси…», выбери Codex или Claude и войди
   в свой аккаунт. Если Codex отсутствует, нажми «Установить и войти…».
   Приложение установит CLI и откроет вход. Для Claude нужен отдельно установленный
   официальный Claude Code CLI; приложение открывает его вход в Terminal.
5. Дождись подтверждения входа и нажми «Запустить прокси».
6. В Figma открой Apollo и выдели экземпляр компонента, например IconView.
   Запусти проверку макета. Сохрани отчёт, если появились неподтверждённые результаты:
   они показывают пробел проверки, а не успешное прохождение.
7. В «Спросить» отправь вопрос: «Какие состояния есть у IconView?».
   Ответ должен прийти через выбранный аккаунт по установленной базе Proxy.

Для этих двух тестов отдельная настройка MCP-генерации не нужна.

## Готовое поручение агенту коллеги

> Помоги установить переданный Apollo Proxy и проверить его на моём Mac.
> Работай с полученным версионным ZIP; не используй пути или аккаунт автора.
> Сначала проверь macOS, архитектуру приложения и встроенного Node, наличие
> предыдущего AP и занятость настроенного порта (по умолчанию 3001). Не останавливай
> чужой процесс и не удаляй мои настройки или историю. Перед заменой попроси
> завершить прежний миниапп через «Выйти», если он работает с активным запросом.
>
> Распакуй приложение, установи в /Applications и запусти. Для внутренней
> ad-hoc сборки разрешается снять quarantine только с этого полученного приложения.
> Через AP → «О прокси…» выбери мой агент и предложи мне завершить личный вход.
> Если Codex не найден, используй кнопку «Установить и войти…».
> Не проси прислать токен аккаунта, не копируй чужую авторизацию и не объявляй вход
> выполненным без успешной проверки CLI. Claude CLI при отсутствии устанавливается
> отдельно по официальной инструкции.
>
> После входа запусти Proxy и проверь GET http://127.0.0.1:3001/health и
> GET http://127.0.0.1:3001/v2/contracts. Сверь фактический dataId и runtime profile
> с поставкой. Затем помоги мне выполнить в Apollo проверку выделенного экземпляра
> и один вопрос в «Спросить». Разделяй успешный HTTP, фактический ответ модели и
> результаты проверки макета. Неподтверждённые нормы не считай PASS.
>
> Для проверки и «Спросить» мне не нужны checkout автора, его workspace,
> Figma MCP или arui-private. Если я отдельно прошу генерацию Figma, настрой
> собственное подключение CLI к Figma MCP и мой целевой fileKey, используй
> scripts/configure-portable.js. Генерация работает только в поддержанном data-MCP
> режиме с принятыми mapping. Не выдумывай отсутствующие ключи, порты или компоненты.
> Built-in native Figma и deterministic generation в этой поставке не допущены.
> Frontend в первой поставке явно недоступен. Его подключение к собственному SDK
> запланировано следующим шагом; не пытайся включать его копированием исходников
> SDK или подстановкой старых proof-файлов. Сохрани прежние личные настройки и историю.
>
> Если передан опубликованный HTTPS-адрес канала, настрой его, проверь обновление,
> установи через «Обновить знания» и проверь current/previous. Обновление применяет
> знания и контракты вместе после завершения активного запроса. При ошибке сохрани
> прежнюю версию и журнал; для возврата используй «Откатить знания».
> Если URL не передан, используй встроенные данные и не подставляй придуманный адрес.
> Заверши коротким отчётом: версия/build, dataId, агент/статус входа, проверенные
> сценарии, фактические ошибки и необходимое действие пользователя.

## Пути и команды для настройки

Собственные данные приложения:

- `~/Library/Application Support/ApolloProxyControl/proxy` — установленный Proxy;
- `…/data-releases/state.json` — атомарный current/previous;
- `…/data-releases/versions/<id>` — неизменяемые снимки данных;
- `…/portable-settings.json` — URL канала, целевой файл и локальная инфраструктура;
- `…/generation` и `…/history` — новые результаты и история;
- учётной записью управляет сам официальный CLI пользователя.

После первого запуска приложения команды выполняются встроенным Node:

```bash
APOLLO_USER_STATE="$HOME/Library/Application Support/ApolloProxyControl"
APOLLO_USER_PROXY="$APOLLO_USER_STATE/proxy"
APOLLO_APP_NODE="/Applications/ApolloProxyControl.app/Contents/Resources/runtime/bin/node"
"$APOLLO_APP_NODE" "$APOLLO_USER_PROXY/scripts/configure-portable.js" --figma-file OWN_FILE_KEY
```

Команда для канала, когда его фактический URL уже выдан командой:

```bash
"$APOLLO_APP_NODE" "$APOLLO_USER_PROXY/scripts/configure-portable.js" --data-url "$APOLLO_REMOTE_CHANNEL_URL"
```

Настройки вступают в силу после завершения активного запроса и перезапуска приложения.
Параметры `--frontend-toolchain` и `--chrome` сохраняют личные настройки для
следующего этапа, но не включают frontend в первом профиле поставки.

CLI диагностика установленного хранилища:

```bash
"$APOLLO_APP_NODE" "$APOLLO_USER_PROXY/scripts/data-release-cli.js" status \
  --store "$APOLLO_USER_STATE/data-releases" \
  --seed "$APOLLO_USER_PROXY/runtime/seed" \
  --runtime "$APOLLO_USER_PROXY/runtime/apollo"
```

Вместо `status` поддерживаются `check`, `update` и `rollback`. Для ручного запуска
из Terminal используй `run` с теми же аргументами после остановки миниаппа:
команда передаёт серверу current snapshot. Не запускай второй сервер на том же порту.

## Подготовка и публикация данных командой

Сборщик `scripts/build-portable-runtime.js` создаёт отдельный code inventory;
`scripts/build-data-release.js` объединяет принятые modern data и legacy knowledge,
проверяет реальные readers и создаёт `stable.json` вместе с архивом.
Источник опубликованного descriptor — Git/HTTPS; архивы должны иметь неизменяемый URL.
Сначала публикуется архив, затем descriptor. Для закрытого endpoint потребитель
использует собственный read-only `APOLLO_DATA_TOKEN`; publisher credentials не передаются.

Новый пакет требует точного runtimeId установленной программы. При изменении кода
сначала выпускается совместимый дистрибутив; updater не подменяет код через данные.
Архив данных не включает .env, историю, CLI credentials, SDK или checkout автора.
Наличие файлов `stable.json`/TGZ в локальной сборке ещё не означает публикацию канала.
