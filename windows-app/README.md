# Apollo Proxy для Windows — тест проверки текстов

Цель первой поставки: редактор запускает UX Writer в Apollo, а запрос модели
выполняется через его личный OpenRouter. Установка Codex или Claude не требуется.
Сохраняются формальная проверка, проверка ответа модели, учёт токенов и отдельное
подтверждение отправки каждого запроса. Локальные CLI и генерация не входят в
приёмку этой поставки.

## Установка и первый запуск

1. Полностью распакуйте ZIP в свою папку, например `Документы\ApolloProxy`.
   Не запускайте `Start.cmd` внутри открытого архива.
2. Откройте `Start.cmd`. Права администратора и установка Node/Python не нужны:
   оба runtime включены в поставку. Если запуск запрещён политиками компании,
   передайте сообщение об ошибке команде Apollo/ИТ; системные политики не меняйте.
3. Введите пароль доступа к знаниям, полученный отдельно от команды Apollo,
   и нажмите «Активировать знания». Дождитесь распаковки и состояния
   «Proxy работает · порт 3001».
4. Введите **свой** API-ключ OpenRouter и нажмите «Подключить». Ключ хранится
   через Windows DPAPI для текущего пользователя; в архиве чужих ключей нет.
   Для запросов нужен доступный баланс OpenRouter.
5. В Figma откройте совместимый Apollo, выделите небольшой макет с текстами
   и запустите UX Writer. В окне Proxy подтвердите отправку текстов и правил.
   Вернитесь в Apollo и проверьте результат. Затем повторите с отменой отправки:
   запрос к модели не должен выполняться.

Закрытие окна сворачивает Proxy в область уведомлений. Двойной щелчок по значку
возвращает настройки. «Завершить» останавливает принадлежащий приложению процесс;
активная проверка должна сначала закончиться.

## Данные и обновления

Настройки, история и журнал живут в `%LOCALAPPDATA%\ApolloProxyControl`.
Ключи находятся в `credentials.dpapi`, журнал — в `logs` (два файла до 5 МиБ каждый).
Пакет знаний сохраняет актуальную версию и одну предыдущую для отката;
активные reader leases обслуживает общий загрузчик Proxy.

В архив включён зашифрованный фиксированный пакет знаний; для первой активации
не требуется скачивать его повторно. «Проверить знания» проверяет этот пакет.
Автообновлений приложения и перехода на новые знания в тестовой поставке нет:
новый комплект передают новым архивом. Не запускайте две копии одновременно. Удаление распакованной
папки не удаляет пользовательскую историю и ключи.

Первая цель — Windows 11 x64. Требуются Windows PowerShell 5.1, системный `tar.exe`,
доступ к OpenRouter. ARM и Windows 10 не приняты.
Запуск скрипта использует ExecutionPolicy только для этого процесса, не меняя
системные настройки; корпоративная Group Policy имеет приоритет.

## Разработка

`controller.js` — приватный JSON-протокол по stdin/stdout, без HTTP-порта настроек.
Он запускает общий сервер, удерживает reader выбранного пакета, проверяет identity
при управлении, запрашивает штатный idle lease перед остановкой и хранит ключ
управления только в памяти. API-ключ модели поступает серверу после подтверждения
конкретного runId, не через argv или окружение worker.

Упаковка читает отдельно принятые code/runtime/bootstrap inputs. Меняющийся checkout
и установленное пользовательское хранилище не используются как неявная подмена.
В ZIP не включаются расшифрованные знания, `.env`, история или ключи автора.
Автоматические fake-тесты не заменяют приёмку Windows, DPAPI и Figma.
